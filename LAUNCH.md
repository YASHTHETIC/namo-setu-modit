# MODIT launch checklist

E2E-tested state: 221 pytest green · web build green · 79-check API journey
green · checkout race-safe · delivery tracking honest · filter sheet fixed.
CI runs all of this on every push (`.github/workflows/ci.yml`). Everything
below is the last mile only the operator can switch on.

## 1. Push latest code + CI green

```bash
git push                      # CI runs: pytest + web checks + build
# https://github.com/YASHTHETIC/modit/actions must be fully green
```

## 2. Deploy the latest build to the VPS

Follow **DEPLOY.md → "Updates after pushing new code"** (git pull →
`npm install --legacy-peer-deps` → alembic → build → `pm2 restart`).
Verify `pm2 status` shows both `online` and `curl` both health endpoints.

## 3. Enable production payments (Razorpay)

Live mode is the only step that cannot be rehearsed offline:

1. Get API keys (Dashboard → Settings → API Keys, switch to **Live**).
2. Put them on the server: append to `/opt/modit/.env`
   ```
   RAZORPAY_KEY_ID=rzp_live_xxx
   RAZORPAY_KEY_SECRET=xxx
   ```
3. `pm2 restart modit-api` (no frontend rebuild needed).
4. Place one **tiny real order end-to-end** with the live keys, then refund
   it from the Razorpay dashboard. Confirm the order shows Paid and the
   admin order page status timeline moves.

Until this is done, checkout works in COD mode — the platform is already
customer-usable; this step only switches on online payment.

## 4. Error alerts (you are the only ops person)

```bash
# in /opt/modit/.env:
ERROR_WEBHOOK_URL=https://discord.com/api/webhooks/xxx/yyy
# pm2 restart modit-api
```
Every unexpected 500 now pings that channel (rate-limited 1/10s). Also
watch GitHub → **Uptime watchdog** action (pings prod every 30 min; stands
red when the site is down). GitHub emails you on failed scheduled runs —
make sure Actions notifications are enabled in your GitHub settings.

## 5. Notifications & messaging status

- Web push: VAPID keys were auto-generated by `deploy/setup.sh` and live in
  `/opt/modit/apps/modit/web/.env.local` — verify the browser once asks and
  receives a notification after "Enable notifications".
- SMS/OTP: unconfigured — login is email/password, which works. Add an SMS
  gateway (`SMS_GATEWAY_URL`, DEPLOY.md/.env.example comments) only when you
  want phone-OTP login.
- Email order confirmations: not built (no SMTP wiring in the checkout
  path). Track page + push + in-app notifications cover status today.
  Add SMTP + order-confirmation email post-launch if customers miss it.

## 6. Post-deploy smoke (10 minutes, ticket-style)

On https://modit.in after the server update:

- [ ] `/` loads, categories render, 0 broken product images
- [ ] `/products` — search, category chip, price chip, sort; **mobile
      filter sheet opens with panel visible** + Escape/overlay/X all close
- [ ] Add 2 items to cart → edit quantity → checkout (login-gated) →
      place a **COD** order → admin sees it → status change to confirmed
- [ ] Admin "Dispatch + delivery" → `/track/<delivery>` shows Order
      placed/Packed/Dispatched all ✓ (no "Calculating…")
- [ ] Razorpay order (after step 3) on a real tiny amount
- [ ] `python scripts/api_journey.py MODIT_JOURNEY_BASE_URL=https://modit.in`
      against prod (or at least `curl /api/v1/healthz` → `"status":"ok"`)

## 7. Data safety

- Nightly dump + restore procedure are documented in DEPLOY.md. Do one
  **restore drill** (to `modit_restore` DB) before launch week — a backup
  has no value until it has been restored once.
- Confirm `/var/backups/modit/` contains a fresh dump after the deploy
  (a snapshot is taken automatically post-deploy).

## 8. Legal/SEO quick pass

- [ ] `/terms`, `/privacy`, `/returns`, `/shipping`, `/contact` pages exist —
      read them once and adjust phone/address/company name for your store
- [ ] Google Search Console: repo has the step-by-step PDF; verify sitemap
      submits (sitemap + robots are served by Next.js)
- [ ] Razorpay requires refund/returns policy to be visibly linked — footer
      should show all policy links
